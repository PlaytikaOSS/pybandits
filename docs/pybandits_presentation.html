A walkthrough for Data Scientists

What is PyBandits?

A Multi-Armed Bandit (MAB) library built on Thompson Sampling — three flavors:

smab = SmabBernoulli(actions={"a1": Beta(), "a2": Beta()})
actions, probs = smab.predict(n_samples=100)   # Thompson sampling
smab.update(actions=actions, rewards=rewards)  # posterior update

The core loop: predict → act → reward → update

Same predict/update API for every bandit · fully serializable to JSON (get_state / from_state)

sMAB vs. cMAB

Both inherit the same BaseMab API — sMAB posterior is exact & O(1); cMAB is an approximate (VI/MCMC), feature-driven model.

The "type" suffixes — one base, five strategies

SuffixClassStrategyBehavior
(none)…BernoulliClassicBanditGreedy on the Thompson sample — pick highest sampled reward
BAI…BernoulliBAIBestActionIdentificationExplore/exploit between best & 2nd-best (exploit_p)

MO…BernoulliMOMultiObjectiveVector rewards → pick from the Pareto front
MOCC…BernoulliMOCCMO + CostControlPareto front and cost-aware
The matrix {Smab, Cmab} × {—, BAI, CC, MO, MOCC} generates every concrete bandit class.

Class architecture at a glance

Strategy (how to choose) is decoupled from the action model (how to estimate); SO/MO/CC mixins compose orthogonally.

base_model.py defines composable mixins, implemented by two model families:

  • BaseModelSO — single objective (n_successes / n_failures, mean, count) · BaseModelMO — list of SO models (one per objective) · BaseModelCC — adds a cost

Beta model (sMAB) — exact & instant

State = n_successes / n_failures · update increments counts · sample = rng.beta(α,β). More data → sharper posterior → less exploration.

Bayesian Neural Network (cMAB)

One-layer BNN = Bayesian logistic regression (the cMAB default) · add hidden_dim_list=[16,8] for a deeper net. A distribution over weights is what gives Thompson Sampling its uncertainty.

BNN — the building blocks

ComponentRole
BnnLayerParamsPer layer: a weight distribution (in×out) + a bias distribution (out)
BnnParamsWhole network: layer params + initial priors (for reset) + embeddings
NormalArrayGaussian prior N(μ,σ) — L2-like, fast
StudentTArrayHeavy-tailed Student-t prior — robust to outliers (default)
FeaturesConfigDescribes mixed numerical + categorical inputs
EmbeddingParamsBayesian embedding matrices for categorical features

Priors are location-scale (μ, σ, optionally ν). cold_start() builds them; layerwise scaling divides σ by √(input_dim) for smoother, GP-like behavior.

BNN — how inference works (NumPyro / JAX)

update() fits the posterior (VI or MCMC); sample_proba() samples weights once and runs the forward pass. VI guide ParameterizedScaleAutoNormal enables warm-starting for online learning.

BNN — the knobs that matter

  • update_method "VI" / "MCMC"; VI sub-methods advi / fullrank_advi
  • Epochs / mini-batches — epochs, batch_size, num_steps
  • Early stopping — patience, tolerance on ELBO convergence
  • Warm start — re-init the variational posterior from the last fit (online learning)
  • Bias priors — bias_std constrains the output logit; calibrate_output_bias sets the intercept to logit(empirical reward rate) on first update → avoids over-optimistic exploration
  • Recent VI stability options — num_particles (ELBO samples/step), gradient clipping (gradient_clip_norm), KL temperature scaling, LR schedules
  • Categorical embeddings — learn dense Bayesian vectors for high-cardinality columns

Quantitative bandits — actions with a value

A quantitative action = a discrete action + a continuous quantity (promo + discount rate, treatment + dosage, strategy + price).

ZoomingQBNN (Quantitative BNN)

ExplorationPer-segment Beta uncertaintyFull posterior over network weights
ScalingCapped # of segmentsSingle network, high-dim friendly
InterpretabilityClear segment → reward mapBlack-box, but flexible

Zooming — adaptive discretization

Refine the grid where it matters: split frequently-sampled segments, merge similar neighbors (Jensen-Shannon divergence).

QBNN — quantity as a learned input

Concatenate quantity + context; the bandit optimizes over q to pick the best action+value. Enabler (#121): sample_proba split into weight-sampling + forward-pass, so the net is evaluated at many q without resampling weights.

ActionsManager & the Meta-Model

ActionsManager owns the per-action models and adds two concerns:

  • Adaptive windowing / change detection — when delta is set, it watches for reward-distribution shifts (KL-based test) and resets + retrains on a trimmed window → robust to non-stationary environments.
  • Memory — replays actions_memory / rewards_memory for warm updates.

BaseMetaModel (refactor #140) sits between the manager and the per-action models, delegating sample_proba / update / reset. CmabPerActionMetaModel enforces cross-action consistency (same input_dim, same update config) — opening the door to shared backbones.

Beyond the core: extra capabilities

  • Transfer learning (transfer.py, #120) — merge two MABs, edit actions on the fly, expand the cMAB feature dimension or BNN architecture without losing learned state
  • Offline Policy Evaluation (offline_policy_evaluator.py, #59) — estimate a policy's value from logged data (propensity scoring + estimators), with Optuna tuning & Bokeh visualization
  • Simulators (smab_simulator.py, cmab_simulator.py) — synthetic environments for testing
  • Serialization everywhere — JSON state with backward-compatible migration

Offline Policy Evaluation — test before you ship

Estimate the value (expected reward) of a candidate policy from logged data collected by a different logging policy — without deploying it online.

API: evaluator.evaluate(mab, logged_data) → DataFrame of value + CI per estimator · update_and_evaluate(...) updates the MAB on the log first.

OPE — estimators trade off bias vs. variance

EstimatorIntuition
ReplayAverage rewards where π_e would pick the logged action — simple, data-hungry
DMPlug logged rewards into a reward model q̂(x,a) → low variance, biased
IPWReweight by w = π_e/π_b → unbiased, high variance
SNIPWSelf-normalize the weights → less variance, slight bias
DRDM baseline + IPW correction on the residual → unbiased & lower variance
DR variantsSwitch-DR, optimistic/pessimistic shrinkage, SubGaussian, Balanced-IPW — tame extreme weights

w = π_e(a|x) / π_b(a|x) · DR is unbiased if either q̂ or π̂_b is right.

Output: estimated value ± CI per estimator (Bokeh bar chart) — compare agreement and pick the estimator you trust.

How the package evolved

Why PyMC → NumPyro? JAX JIT/XLA, in-graph mini-batched SVI (lax.scan), faster NUTS, optax optimizers — big speed & scalability gains for the BNN.

Takeaways

  • One API, many bandits: predict / update on top of BaseMab, fully serializable.
  • Two axes of choice: the model (Beta ↔ BNN ↔ Zooming/QBNN) × the strategy (Classic / BAI / CC / MO / MOCC).
  • Beta = exact & instant for contextless problems; BNN = uncertainty-aware deep model for contextual ones; a one-layer BNN is Bayesian logistic regression.
  • Quantitative bandits handle continuous action values — discretized (Zooming) or learned (QBNN).
  • The codebase moved to a modern Bayesian stack (NumPyro/JAX + Pydantic v2) and gained transfer learning, OPE, multi-objective, embeddings, and non-stationarity handling.
